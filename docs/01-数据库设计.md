# 01 · 数据库设计

> MySQL 8.4 LTS / InnoDB / `utf8mb4` / `utf8mb4_0900_ai_ci` / 时区 `Asia/Shanghai`
> 所有表由 Flyway 管理：`V1__init_schema.sql` 建表，`V2__init_data.sql` 初始化数据，
> `V3`–`V14` 做增量调整（字段加宽、消息、AI、外键、菜单补充）。

---

## 一、设计原则

| 项 | 规则 |
|---|---|
| 主键 | `bigint AUTO_INCREMENT`（MyBatis-Plus `AUTO`），从不在应用侧生成；**接口序列化为 String** |
| 审计字段 | 所有表必须含 `create_by / create_time / update_by / update_time`，由 `MetaObjectHandler` 自动填充 |
| 逻辑删除 | 业务表含 `del_flag tinyint`，`0` 存在 / `1` 删除；`@TableLogic` |
| 状态字段 | `status tinyint`，`0` 正常 / `1` 停用 |
| 金额 | `decimal(18,2)`，禁止 `float/double` |
| 时间 | `datetime(3)`，精确到毫秒 |
| 索引命名 | 普通索引 `idx_列名`，唯一索引 `uk_列名` |
| 外键 | **不使用**，由应用层保证；便于分库分表和批量操作 |
| 字段注释 | 每个字段必须有 `COMMENT` |

### 逻辑删除与唯一索引的冲突

`sys_user.username` 需要唯一，但软删除后记录仍占着唯一键，重建同名用户会冲突。

**本项目采用"删除时重命名"策略**：删除用户时，同时把 `username` 改写为
`原用户名#del_{user_id}`。这样唯一索引可以保持 `uk_username(username)` 的简单形式，
不需要把 `del_flag` 塞进联合索引（那会导致同一用户名只能被删除一次）。

```sql
-- 删除用户时在同一事务内执行
UPDATE sys_user
   SET del_flag = 1,
       username = CONCAT(username, '#del_', user_id),
       update_by = #{operator}, update_time = NOW(3)
 WHERE user_id = #{userId} AND del_flag = 0;
```

`sys_role.role_key`、`sys_dict_type.dict_type`、`sys_config.config_key` 同理。

### 3.1 部门表

CREATE TABLE `sys_dept` (
  `dept_id`     bigint       NOT NULL AUTO_INCREMENT COMMENT '部门ID',
  `parent_id`   bigint       NOT NULL DEFAULT 0      COMMENT '父部门ID，0为顶级',
  `ancestors`   varchar(500) NOT NULL DEFAULT ''     COMMENT '祖级列表，逗号分隔，如 0,100,101',
  `dept_name`   varchar(30)  NOT NULL                COMMENT '部门名称',

  `phone`       varchar(11)           DEFAULT NULL   COMMENT '联系电话',
  `email`       varchar(50)           DEFAULT NULL   COMMENT '邮箱',
  `status`      tinyint      NOT NULL DEFAULT 0      COMMENT '状态：0正常 1停用',
  `del_flag`    tinyint      NOT NULL DEFAULT 0      COMMENT '删除标志：0存在 1删除',
  `create_by`   varchar(64)           DEFAULT NULL   COMMENT '创建者',
  `create_time` datetime(3)           DEFAULT NULL   COMMENT '创建时间',
  `update_by`   varchar(64)           DEFAULT NULL   COMMENT '更新者',

### 3.4 菜单表

```sql
CREATE TABLE `sys_menu` (
  `menu_id`     bigint       NOT NULL AUTO_INCREMENT COMMENT '菜单ID',
  `menu_name`   varchar(50)  NOT NULL                COMMENT '菜单名称',
  `parent_id`   bigint       NOT NULL DEFAULT 0      COMMENT '父菜单ID，0为顶级',
  `order_num`   int          NOT NULL DEFAULT 0      COMMENT '显示顺序',
  `path`        varchar(200)          DEFAULT NULL   COMMENT '路由地址',
  `component`   varchar(255)          DEFAULT NULL   COMMENT '组件路径，目录为 Layout',
  `query`       varchar(255)          DEFAULT NULL   COMMENT '路由参数',
  `is_frame`    tinyint   NOT NULL DEFAULT 0      COMMENT '是否外链：0否 1是',
  `is_cache`    tinyint   NOT NULL DEFAULT 0      COMMENT '是否缓存：0不缓存 1缓存',
  `menu_type`   char(1)      NOT NULL                COMMENT '类型：M目录 C菜单 F按钮',
  `visible`     tinyint   NOT NULL DEFAULT 0      COMMENT '是否显示：0显示 1隐藏',
  `status`      tinyint      NOT NULL DEFAULT 0      COMMENT '状态：0正常 1停用',
  `perms`       varchar(100)          DEFAULT NULL   COMMENT '权限字符，如 system:user:add',
  `icon`        varchar(100)          DEFAULT NULL   COMMENT '菜单图标',
  `create_by`   varchar(64)           DEFAULT NULL,
  `create_time` datetime(3)           DEFAULT NULL,
  `update_by`   varchar(64)           DEFAULT NULL,
  `update_time` datetime(3)           DEFAULT NULL,
  PRIMARY KEY (`menu_id`),
  KEY `idx_parent_id` (`parent_id`),
  KEY `idx_perms` (`perms`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='菜单权限表';
```

**`menu_type` 语义（重要）**：

| 值 | 含义 | 前端表现 | 是否生成路由 |
|---|---|---|---|
| `M` | 目录 | 侧边栏一级分组，可折叠 | 是（`Layout` 容器） |
| `C` | 菜单 | 一个具体页面 | 是（叶子路由） |
| `F` | 按钮 | 不显示，只用于权限校验 | 否 |

### 站内消息（V6 新增）

公告发布后投递到用户收件箱。`sys_message` 存消息本体，`sys_message_user` 存收件人与已读状态。

```sql
CREATE TABLE `sys_message` (
  `message_id`  bigint       NOT NULL AUTO_INCREMENT COMMENT '消息ID',
  `title`       varchar(100) NOT NULL COMMENT '标题',
  `content`     text                  DEFAULT NULL COMMENT '内容',
  `msg_type`    tinyint      NOT NULL DEFAULT 1 COMMENT '类型：1公告 2系统 3个人',
  `level`       tinyint      NOT NULL DEFAULT 0 COMMENT '级别：0普通 1重要 2紧急',
  `link`        varchar(200)          DEFAULT NULL COMMENT '点击跳转的前端路由',
  `source_id`   bigint                DEFAULT NULL COMMENT '来源业务ID（如公告ID）',
  `create_by`   varchar(64)           DEFAULT NULL,
  `create_time` datetime(3)           DEFAULT NULL,
  PRIMARY KEY (`message_id`),
  KEY `idx_message_source` (`source_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='站内消息';

CREATE TABLE `sys_message_user` (
  `id`          bigint      NOT NULL AUTO_INCREMENT,
  `message_id`  bigint      NOT NULL COMMENT '消息ID',
  `user_id`     bigint      NOT NULL COMMENT '接收人',
  `read_flag`   tinyint     NOT NULL DEFAULT 0 COMMENT '0未读 1已读',
  `read_time`   datetime(3)          DEFAULT NULL,
  `create_time` datetime(3)          DEFAULT NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_message_user` (`message_id`, `user_id`),
  KEY `idx_user_unread` (`user_id`, `read_flag`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='站内消息收件人';
```

**为什么拆两张表**：正文只存一份，收件人各自一行记录已读。公告修改后，
所有收件人点进去看到的都是最新版（正文不复制进收件箱）。

### AI 助手（V7 / V10 新增）

`sys_ai_session` 与 `sys_ai_message` 保存对话历史，`sys_ai_config` 存模型参数与加密后的 API Key。

配置单独成表（V10）的原因：密钥不能和普通参数放在一起 —— `sys_config` 只要 `system:config:list`
权限就能看到明文，而 AI 配置只对管理员开放。

```sql
CREATE TABLE `sys_ai_session` (
  `session_id`  bigint       NOT NULL AUTO_INCREMENT COMMENT '会话ID',
  `user_id`     bigint       NOT NULL COMMENT '所属用户',
  `title`       varchar(100)          DEFAULT NULL COMMENT '会话标题（取首条提问）',
  `model`       varchar(64)           DEFAULT NULL COMMENT '模型名',
  `create_time` datetime(3)           DEFAULT NULL,
  `update_time` datetime(3)           DEFAULT NULL,
  PRIMARY KEY (`session_id`),
  KEY `idx_ai_session_user` (`user_id`, `update_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='AI 会话';

CREATE TABLE `sys_ai_message` (
  `message_id`        bigint      NOT NULL AUTO_INCREMENT,
  `session_id`        bigint      NOT NULL COMMENT '会话ID',
  `role`              varchar(16) NOT NULL COMMENT 'user / assistant',
  `content`           mediumtext           DEFAULT NULL COMMENT '消息内容',
  `prompt_tokens`     int                  DEFAULT NULL COMMENT '输入 token',
  `completion_tokens` int                  DEFAULT NULL COMMENT '输出 token',
  `duration_ms`       bigint               DEFAULT NULL COMMENT '耗时',
  `create_time`       datetime(3)          DEFAULT NULL,
  PRIMARY KEY (`message_id`),
  KEY `idx_ai_message_session` (`session_id`, `message_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='AI 消息';

CREATE TABLE `sys_ai_config` (
  `ai_config_id` bigint       NOT NULL AUTO_INCREMENT,
  `provider`     varchar(32)  NOT NULL DEFAULT 'deepseek' COMMENT '服务商',
  `model`        varchar(64)  NOT NULL COMMENT '模型名',
  `base_url`     varchar(200) NOT NULL COMMENT '接口地址',
  `api_key`      text                  DEFAULT NULL COMMENT '密钥（AES-GCM 加密后存储）',
  `temperature`  decimal(3, 2) NOT NULL DEFAULT 0.70 COMMENT '温度',
  `max_tokens`   int          NOT NULL DEFAULT 4096 COMMENT '最大输出 token',
  `enabled`      tinyint      NOT NULL DEFAULT 1 COMMENT '是否启用',
  `update_by`    varchar(64)           DEFAULT NULL,
  `update_time`  datetime(3)           DEFAULT NULL,
  PRIMARY KEY (`ai_config_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='AI 配置';
```

**密钥为什么加密存**：`api_key` 用 AES-GCM 加密，密钥来自环境变量 `AI_CONFIG_SECRET`；
表被拖走也拿不到明文，接口只回显掩码（`xxxx****xxxx`）。

## 五、数据权限字段说明

`sys_role.data_scope` 决定该角色能看到哪些行数据：

| 值 | 含义 | 生成条件（以 `sys_user` 为例） |
|---|---|---|
| `1` | 全部数据 | 不附加条件 |
| `2` | 自定义部门 | `dept_id IN (SELECT dept_id FROM sys_role_dept WHERE role_id IN (...))` |
| `3` | 本部门 | `dept_id = #{user.deptId}` |
| `4` | 本部门及以下 | `dept_id IN (SELECT dept_id FROM sys_dept WHERE dept_id = #{deptId} OR FIND_IN_SET(#{deptId}, ancestors))` |
| `5` | 仅本人 | `user_id = #{userId}`（用户表）或 `create_by = #{username}`（其他表） |

**多角色合并规则**：取所有角色中**最宽松**的一个（`1` > `2` > `4` > `3` > `5`）。

**注意**：自动拼条件只对 MyBatis-Plus 生成的 SQL 生效；手写 XML 的 SQL 必须显式调用
`DataScopeHelper.apply(...)`，详见 [02-认证与权限设计](02-认证与权限设计.md#七数据权限)。

## 六、常用查询示例

```sql
-- 查询用户的权限字符集合（登录时执行一次，结果缓存 Redis）
SELECT DISTINCT m.perms
  FROM sys_menu m
  JOIN sys_role_menu rm ON rm.menu_id = m.menu_id
  JOIN sys_user_role ur ON ur.role_id = rm.role_id
 WHERE ur.user_id = ?
   AND m.status = 0
   AND m.perms IS NOT NULL
   AND m.perms <> '';

-- 查询用户的角色标识（用于前端判断）
SELECT r.role_key
  FROM sys_role r
  JOIN sys_user_role ur ON ur.role_id = r.role_id
 WHERE ur.user_id = ? AND r.status = 0 AND r.del_flag = 0;

-- 查询菜单树（用于动态路由，只取 M 和 C）
SELECT *
  FROM sys_menu
 WHERE menu_type IN ('M','C') AND status = 0
   AND menu_id IN (
       SELECT rm.menu_id FROM sys_role_menu rm WHERE rm.role_id IN (...)
   )
 ORDER BY parent_id, order_num;
```

## 七、Flyway 约定

| 规则 | 说明 |
|---|---|
| 命名 | `V{序号}__{描述}.sql`，序号连续 |
| 只增不改 | 已发布的脚本**禁止修改**，改结构用新脚本 |
| 禁止 clean | 生产环境 `spring.flyway.clean-disabled=true` |
| 生产策略 | 只执行 `migrate`，禁止 `baseline` 覆盖已有库 |
| 大表变更 | 加索引用 `ALGORITHM=INPLACE, LOCK=NONE`（MySQL 8 多数情况自动） |
| 脚本内容 | 一个脚本只做一件事（建表 / 加索引 / 改字段分开） |

```yaml
spring:
  flyway:
    enabled: true
    locations: classpath:db/migration
    baseline-on-migrate: true
    clean-disabled: true
    validate-on-migrate: true
```
