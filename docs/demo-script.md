# 60 秒演示录屏分镜

一段 60 秒的录屏，让人在不读文档的情况下看懂这个项目是什么、能做什么。

## 录制前提

- 已执行 `docker compose up -d` 并等待 4 个服务 healthy
- 浏览器窗口 **1440×900**（与 `docs/screenshots/` 一致），缩放 100%
- 界面语言：中文
- 提前登录一次再退出，确保验证码、菜单、字体都已缓存，录制时不会卡顿
- 光标移动放慢一半，点击前停顿 0.2 秒，让观众看清落点

## 分镜表

| 时间 | 画面 | 操作 | 想让观众看到什么 |
|---|---|---|---|
| 0–5s | 登录页 | 打开 `http://localhost:3300/` | 一条命令起来就能看到完整登录页，不是裸接口 |
| 5–12s | 登录页 | 输入 `admin` / `admin123`，填验证码，点「登 录」 | 图形验证码 + 账号密码的完整认证链路 |
| 12–20s | 首页 | 登录后停在首页，鼠标沿左侧菜单从上滑到下 | 侧边栏、页签、当前权限，整体框架形态 |
| 20–30s | 用户管理 | 展开「系统管理」→ 点「用户管理」，在「用户名」搜索框输入 `li` 回车 | 搜索条件、表格、分页、操作列（修改 / 删除 / 重置密码） |
| 30–45s | 新增用户弹窗 | 点「新增」→ 填 用户名 `demo01`、昵称 `演示用户`、密码 `abc123456`、部门选「研发部」→ 点确定 | 一个 `schema.ts` 就能生成完整表单，字段校验、字典下拉都是自动的 |
| 45–55s | 服务监控 | 展开「系统监控」→ 点「服务监控」，鼠标扫过 CPU 使用率、物理内存、JVM 堆、依赖服务 | 真实运行指标（Linux、MySQL、Redis 版本都来自容器） |
| 55–60s | 停留 | 画面停在服务监控页 | 收尾，给观众时间看清 |

## 旁白要点（可选，录屏时不必配音）

1. 一条 `docker compose up -d` 拉起 MySQL + Redis + 后端 + 前端
2. 登录走自建 JWT + Redis 会话白名单，不依赖 OAuth2 授权服务器
3. 菜单和按钮权限都由后端下发，前端动态注册路由
4. 用户管理页由 `schema.ts` 配置驱动，没有手写 CRUD
5. 服务监控里的数据是容器内真实指标

## 剪辑要求

- **不要**剪掉验证码输入过程，那是真实链路的一部分
- **不要**拼接或伪造数据，新增用户这条记录会真实写库
- 录制结束后可以重置数据：`docker compose down -v && docker compose up -d`

## 工具建议

- macOS：QuickTime Player（「文件 → 新建屏幕录制」）或 OBS
- 输出：MP4 / H.264，30fps，1440×900；如果放 GitHub，建议 ≤ 10MB，必要时用 `ffmpeg` 压一下
