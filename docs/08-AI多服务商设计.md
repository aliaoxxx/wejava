# 08 · AI 多服务商设计

> 目标：把「只能配一个 DeepSeek」改造成「可配多个国产模型端点，聊天时自由切换」。
> 状态：**设计稿**（待评审，尚未实现）。

---

## 一、现状与问题

| 项 | 现状 | 问题 |
|---|---|---|
| 存储 | `sys_ai_config` 字段齐全（provider / model / base_url / api_key / temperature / max_tokens） | 只用一行：`selectOne(... .last("LIMIT 1"))` |
| `provider` 字段 | 有，但从不参与逻辑 | 纯展示，换厂商仍要手工改 base_url |
| 客户端 | `DeepSeekClient` 用 `HttpClient` 请求 `baseUrl + "/chat/completions"` | **已经是 OpenAI 兼容协议**，只是名字叫 DeepSeek |
| base_url 拼接 | 直接字符串拼接 | 未处理尾斜杠，智谱给的地址是 `.../v4/`，会拼成 `//chat/completions` |
| 前端 | 单表单（服务商 / 模型 / 地址 / 密钥） | 无法管理多个端点 |

**关键结论**：协议层不用重写。国产厂商（DeepSeek、通义、智谱、Kimi、豆包、千帆、混元、星火、硅基流动）
全部提供 OpenAI 兼容接口，**一个适配器即可覆盖**。工作集中在配置模型、接口和前端交互。

## 二、设计原则

1. **按协议适配，不按厂商适配** —— 厂商差异收敛到「配置项 + 预设」，不进代码分支。
2. **模型名不硬编码** —— 见下方实证；模型名由用户填写或从厂商接口拉取。
3. **一行配置 = 一个模型端点**（provider + model + base_url + key + 采样参数）。
4. **默认项唯一** —— 聊天未指定时使用 `is_default = 1` 那一行。

> **为什么强调"模型名不硬编码"**
> 写这份设计时查了官方文档：智谱已迭代到 `glm-5.3`，Kimi 已发布 `K3.1 Pro`。
> 把半年前的 `glm-4-plus`、`moonshot-v1-8k` 写进代码，上线即过时。

## 三、数据模型（V15）

```sql
ALTER TABLE `sys_ai_config`
    ADD COLUMN `config_name` varchar(64)  NOT NULL DEFAULT '' COMMENT '显示名称，如「智谱 GLM」',
    ADD COLUMN `protocol`    varchar(32)  NOT NULL DEFAULT 'openai' COMMENT '协议：openai（当前唯一实现）',
    ADD COLUMN `is_default`  tinyint      NOT NULL DEFAULT 0 COMMENT '聊天默认使用的端点',
    ADD COLUMN `sort`        int          NOT NULL DEFAULT 0 COMMENT '列表排序',
    ADD COLUMN `remark`      varchar(200)          DEFAULT NULL COMMENT '备注，可放厂商文档链接';

-- 现有那行补上显示名，并设为默认（保证升级后聊天立即可用）
UPDATE `sys_ai_config` SET `config_name` = CONCAT(`provider`, ' ', `model`)
WHERE `config_name` = '';
UPDATE `sys_ai_config` SET `is_default` = 1 ORDER BY `ai_config_id` LIMIT 1;
```

**约束**

- `is_default = 1` 的行唯一：由服务层保证，切换默认时先全部置 0。
- 默认行**不允许删除**，避免聊天功能突然不可用。

## 四、接口设计

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/system/ai-config/list` | `system:ai:config` | 配置列表，密钥只回显掩码 |
| GET | `/system/ai-config/{id}` | 同上 | 单条详情 |
| POST | `/system/ai-config` | 同上 | 新增 |
| PUT | `/system/ai-config/{id}` | 同上 | 修改（密钥留空 = 保留原值） |
| DELETE | `/system/ai-config/{id}` | 同上 | 删除，默认项拒绝 |
| PUT | `/system/ai-config/{id}/default` | 同上 | 设为默认 |
| GET | `/system/ai-config/providers` | 同上 | 厂商预设（含 base_url、文档链接） |
| GET | `/system/ai-config/{id}/models` | 同上 | **服务端代理**拉取模型列表 |
| POST | `/system/ai-config/{id}/test` | 同上 | 测试连接，返回耗时与错误原因 |

**两条硬性要求**

1. **模型列表必须服务端代理**：浏览器不能拿到密钥直连厂商，否则密钥会出现在网络面板里。
2. **测试连接与拉取列表要限流**：复用现有 `@RateLimit`，避免被当成扫描器。

聊天接口增加可选参数 `configId`：

```
POST /ai/chat/{sessionId}?configId=12      # 指定端点
POST /ai/chat/{sessionId}                  # 不指定 → 用默认端点
```

会话表 `sys_ai_session` 已有 `model` 字段，建议**每条消息**记录实际使用的 `configId + model`，
便于排查"这条回复是哪个模型出的"。

## 五、后端分层

```
ai/
├── client/
│   ├── ChatClient.java              # 接口：void stream(ChatRequest, Consumer<Chunk>)
│   ├── OpenAiCompatibleClient.java  # 由 DeepSeekClient 改名，逻辑不变
│   └── AiClientFactory.java         # 按 protocol 选实现
├── model/{entity,form,vo}/…         # 补 config_name / is_default / protocol / sort
├── service/AiConfigService.java     # 增加 list / create / update / delete / setDefault / byId
└── controller/AiConfigController.java
```

**必须修的坑（已定位）**

```java
// 现状：baseUrl 直接拼接，智谱的 .../v4/ 会变成 .../v4//chat/completions
String url = baseUrl + "/chat/completions";

// 修复：归一化后再拼
String url = stripTrailingSlash(baseUrl) + "/chat/completions";
```

**流式解析要兼容的两种增量**

```json
{"choices":[{"delta":{"content":"正文"}}]}           // 常规
{"choices":[{"delta":{"reasoning_content":"思考"}}]}  // DeepSeek / 智谱 的推理模型
```

推理内容不进数据库（太占空间），只在流中推给前端；正式回答才落 `sys_ai_message`。

## 六、前端交互

### 6.1 AI 配置页（`views/ai/config.vue`）

单表单改为 **列表 + 弹窗**：

| 列 | 内容 |
|---|---|
| 名称 | `config_name` |
| 厂商 | provider（带图标或徽章） |
| 模型 | model |
| 默认 | 徽章，点击可切换 |
| 状态 | 启用 / 停用 |
| 操作 | 编辑 / 测试 / 删除 |

**新增/编辑弹窗字段**

| 字段 | 交互 |
|---|---|
| 厂商 | 下拉，含「自定义」；选中后自动填 base_url 与厂商文档链接 |
| 显示名 | 文本，默认取厂商名 |
| Base URL | 文本，自定义时必填 |
| 模型 | 输入框 + **「拉取模型列表」按钮**（调后端代理接口，下拉选择或手工填） |
| API Key | 密码框；编辑时留空表示不修改，占位显示掩码 |
| 温度 / 最大 token | 数字输入，温度上限按厂商提示（智谱 0–1，其余 0–2） |
| 启用 / 默认 | 开关 |

弹窗底部两个按钮：**测试连接**（不保存也能测）、保存。

### 6.2 AI 助手页（`views/ai/index.vue`）

顶部加模型选择器：

- 只列出 `enabled = 1` 的端点
- 默认选中 `is_default`，并记住用户上次选择（localStorage）
- 切换后下一条消息立即生效；历史消息不受影响

## 七、兼容性处理清单

| 问题 | 处理方式 |
|---|---|
| base_url 尾斜杠 | 拼接前统一去掉，再补 `/chat/completions` |
| 模型名随版本变化 | 不硬编码；提供拉取按钮，拉不到则手工填 |
| 温度范围不同 | 前端按 `provider` 给提示；后端只做 0–2 的粗校验 |
| 推理增量 `reasoning_content` | 流式解析兼容，不落库 |
| token 统计 | OpenAI 需 `stream_options.include_usage`；DeepSeek / 智谱默认返回。解析时容错 |
| 401 / 429 / 余额不足 | 统一映射成中文提示，不透传上游原始报文 |
| 超时 | 现有 5 分钟偏紧，长上下文模型建议改为可配置（默认 5 分钟，最大 15 分钟） |

## 九、安全

- 密钥沿用 `AesUtils`（AES-GCM + `AI_CONFIG_SECRET`）加密存储，列表只回显掩码。
- 模型列表与测试连接由**服务端**发起，密钥不进浏览器。
- 两个新接口挂 `@RateLimit`，防止被当作探测工具。
- 删除默认端点、把端点全部停用，都会让聊天不可用 —— 服务层要拦住，给出明确提示。

## 十、迁移与回滚

| 场景 | 做法 |
|---|---|
| 升级 | Flyway V15 自动加列；旧配置补 `config_name` 并设为默认，聊天无感知 |
| 回滚 | 旧版代码忽略新增列，直接可用；无需回滚 SQL |
| 数据兼容 | 新增列都有默认值，`INSERT` 不写这些列也能跑 |
