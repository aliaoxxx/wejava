# WeJavaAdmin 避坑清单

> 技术栈基线：Spring Boot 4.1.x / Spring Security 7 / MyBatis-Plus 3.5.18 / MySQL 8.4 / Redis 8 / Vue 3.5 + Element Plus
> 用法：新项目启动时逐条过一遍；上线前按第 12 节验收。

---

## 0. 优先级说明

- 🔴 **P0**：不处理一定出事，且出事时很难查（线上事故级）
- 🟡 **P1**：大概率踩，浪费半天到两天
- 🟢 **P2**：规范性建议，影响长期可维护性

---

## 1. 依赖与版本（Boot 4 专章）

Spring Boot 4 不是"改个版本号"，它同时换了 Spring Framework 7、Jakarta EE 11、Jackson 3 和 starter 组织方式。

- [ ] 🔴 **starter 全部改名**
  `spring-boot-starter-web` → `webmvc`；`-aop` → `-aspectj`；`-json` → `-jackson`；
  `-oauth2-client` → `-security-oauth2-client`；`-oauth2-resource-server` → `-security-oauth2-resource-server`。
  旧名字还能编译，但属于弃用状态，别在新项目里用。

- [ ] 🔴 **Jackson 3 包名迁移**
  `com.fasterxml.jackson.databind.*` → `tools.jackson.databind.*`
  `com.fasterxml.jackson.core.*` → `tools.jackson.core.*`
  **例外**：`com.fasterxml.jackson.annotation.*`（`@JsonProperty`、`@JsonIgnore`）不变。
  自查命令：`grep -rn "import com.fasterxml.jackson" src/ | grep -v annotation`

- [ ] 🔴 **Boot 自己的 Jackson 集成类也改了名**
  `Jackson2ObjectMapperBuilderCustomizer` → `JsonMapperBuilderCustomizer`
  **正确包名是 `org.springframework.boot.jackson.autoconfigure`**（网上不少迁移文章漏了 `.autoconfigure`，直接编译不过）。
  `@JsonComponent` → `@JacksonComponent`
  `JsonObjectSerializer` → `ObjectValueSerializer` / `JsonObjectDeserializer` → `ObjectValueDeserializer`

- [ ] 🔴 **Jackson 配置项换了命名空间**
  `spring.jackson.write.*` / `spring.jackson.read.*` / `spring.jackson.parser.*`
  → `spring.jackson.json.write.*` / `spring.jackson.json.read.*`
  老配置不会报错，只是**静默不生效**，日期格式、null 处理全部回落默认值。

- [ ] 🔴 **`spring.jackson.json.*` 只接受 `JsonWriteFeature` / `JsonReadFeature` 枚举**
  **实测踩坑（Boot 4.1.2 + Jackson 3.1.2）**：写
  ```yaml
  spring.jackson.json.write.write-dates-as-timestamps: false
  ```
  应用直接启动失败：
  ```
  Failed to bind properties under 'spring.jackson.json.write'
  Caused by: No enum constant tools.jackson.core.json.JsonWriteFeature.write-dates-as-timestamps
  ```
  因为 `WRITE_DATES_AS_TIMESTAMPS` 属于 databind 层的 `SerializationFeature`，不是 `JsonWriteFeature`。
  **正确做法**：用 `JsonMapperBuilderCustomizer` 编程式配置，别往 `spring.jackson.json.*` 里硬塞。

- [ ] 🟡 **Jackson 行为默认值变了，别假设输出逐字节一致**
  过渡期可先加 `spring.jackson.use-jackson2-defaults=true` 对齐 3.x 行为，稳定后逐项去掉。

- [ ] 🔴 **`spring-boot-starter-flyway` / `-liquibase` / `-restclient` / `-webclient` 需要显式引入**
  Boot 4 不再"classpath 有就自动配置"。症状：加了 Flyway 依赖但迁移脚本不执行、`RestClient.Builder` 注入不到。

- [ ] 🔴 **Flyway 10+ 的数据库方言拆成了独立模块**
  只引 `spring-boot-starter-flyway` 不够，MySQL 必须再引：
  ```xml
  <dependency>
      <groupId>org.flywaydb</groupId>
      <artifactId>flyway-mysql</artifactId>
      <version>${flyway.version}</version>
  </dependency>
  ```
  否则启动报 `No database found to handle jdbc:mysql://...`。
  另外：测试用 H2 时记得 `spring.flyway.enabled=false`，否则会拿 MySQL 脚本去 H2 上跑。

- [ ] 🟡 **Flyway 对"比它验证过更新的数据库版本"只告警不阻塞**
  实测 MySQL 9.6 + Flyway 11：`Using MySQL 9.6 which is newer than the version Flyway has been verified with. The latest verified version of MySQL is 9.4.`
  **只是 WARN，迁移照常执行**。但升级数据库大版本前要跑一次全量迁移验证。

- [ ] 🟡 **`tinyint(1)` 的显示宽度已废弃**
  MySQL 会告警：`Integer display width is deprecated and will be removed in a future release`。
  直接写 `tinyint` 即可，语义不受影响（布尔值照样 0/1）。

- [ ] 🟡 **Undertow 已不再支持**（未实现 Servlet 6.1），只能用 Tomcat 或 Jetty。

- [ ] 🟡 **测试相关**
  `@MockBean` → `@MockitoBean`；`@SpyBean` → `@MockitoSpyBean`
  `@SpringBootTest` 不再自动配置 MockMvc，必须加 `@AutoConfigureMockMvc`
  `TestRestTemplate` → `RestTestClient` + `@AutoConfigureRestTestClient`

- [ ] 🟡 **健康探针默认开启**：`/livez`、`/readyz` 开箱即用，生产环境确认是否要暴露。

- [ ] 🟡 **MyBatis-Plus 必须用 Boot4 专用 starter**
  `mybatis-plus-spring-boot4-starter`（3.5.13 起提供）+ 必引 `mybatis-plus-jsqlparser`。
  只引 starter 不引 jsqlparser → 分页、数据权限插件启动报错。

- [ ] 🟡 **用 `spring-boot-properties-migrator` 扫一遍配置**
  临时加 runtime 依赖，启动时会把所有失效的配置项打出来，改完记得移除。

- [ ] 🟢 **锁死依赖版本**：`mvn dependency:tree` 存档，CI 里对比，防止某次 merge 悄悄降级。

## 2. 认证与会话

- [ ] 🔴 **Long 型主键传到前端精度丢失**
  雪花 ID 19 位，超过 JS `Number.MAX_SAFE_INTEGER`（2^53-1），前端拿到 `...000`，编辑/删除错行。
  做法：全局把 `Long` 序列化成 String。
  ```java
  @Bean
  JsonMapperBuilderCustomizer longToString() {
      return builder -> builder.addModule(new SimpleModule()
          .addSerializer(Long.class, ToStringSerializer.instance)
          .addSerializer(Long.TYPE, ToStringSerializer.instance));
  }
  ```
  或者前端用 `json-bigint`。**后端做更省事，全项目只有一处。**

- [ ] 🔴 **JWT 必须可撤销**
  纯 JWT 是无状态的，登出/改密/禁用账号后 token 依然有效。
  做法：签发时带 `jti`，Redis 存 `login:token:{userId}:{jti}`，过滤器每次校验存在性。
  这也是**踢下线、单点登录、改密强制重登**的统一实现点。

- [ ] 🔴 **401 和 403 要分清**
  401 = 没登录/登录过期 → 前端跳登录页
  403 = 登录了但没权限 → 前端弹提示，**不能跳登录页**（会陷入死循环）

- [ ] 🔴 **认证异常不会走 `@RestControllerAdvice`**
  Filter 层抛的异常在 DispatcherServlet 之外，必须配 `AuthenticationEntryPoint`（401）和 `AccessDeniedHandler`（403），且返回 JSON 而不是重定向。

- [ ] 🟡 **密码：BCrypt，绝不用 MD5/SHA**
  用 `BCryptPasswordEncoder`。如果以后要换算法，用 `DelegatingPasswordEncoder`，库里存 `{bcrypt}$2a$...`，方便平滑迁移。

- [ ] 🟡 **防爆破**：登录失败计数放 Redis（`login:fail:{username}`，5 次锁 15 分钟），配图形验证码。纯前端验证码没用。

- [ ] 🟡 **JWT secret 管理**：至少 256 bit，不要硬编码进代码和 Git，走环境变量/配置中心，并预留轮换方案（双 key 并存过渡）。

- [ ] 🟡 **双 token 设计**：access token 30 分钟，refresh token 7 天且存 Redis、一次一换（rotation）。access 过期用 refresh 静默续期，用户无感。

- [ ] 🟡 **刷新接口并发**：前端 5 个请求同时 401 会触发 5 次 refresh，后发的可能作废先发的 token。前端必须做**单例刷新队列**（见第 8 节）。

- [ ] 🟢 **登出要真删 Redis key**，不能只清前端 localStorage。

## 3. 权限与越权

- [ ] 🔴 **前端隐藏 ≠ 后端放行**
  `v-hasPerm` 只控制"看不看得见"，接口必须每个都加 `@PreAuthorize("hasAuthority('system:user:add')")`。
  漏一个就是后台被越权调用的入口。

- [ ] 🔴 **水平越权：所有按 id 操作的接口都要校验归属**
  `GET /api/order/{id}` 只判断"登录了"不够，还要判断"这单是不是你的"。
  最常见漏洞形态：改 URL 里的 id 就能看别人数据。

- [ ] 🔴 **`hasRole` 和 `hasAuthority` 不能混用**
  `hasRole("ADMIN")` 会自动加 `ROLE_` 前缀去匹配 `ROLE_ADMIN`，`hasAuthority` 不会。
  **统一只用 `hasAuthority` + 数据库里的 `perms` 字符串**（`system:user:add`）。

- [ ] 🟡 **超管用独立标识**
  用 `user_id = 1` 或 `is_admin` 字段判断，不要用"这个人拥有所有角色"来实现——新增权限时超管会莫名失去权限。

- [ ] 🟡 **权限缓存要能失效**
  登录时把 `perms` 装配进 `UserDetails` 并缓存 Redis。改了角色权限后必须清缓存，否则用户要等 token 过期才生效。

- [ ] 🔴 **数据权限改写只对 MP 生成的 SQL 生效**
  `DataPermissionInterceptor` 不会动你手写的 XML SQL。
  手写 SQL 要手动拼条件，或者干脆把数据权限表字段暴露给 XML 用。

- [ ] 🟡 **菜单表设计**：`menu_type`（M 目录 / C 菜单 / F 按钮）+ `perms` 字段。按钮权限靠 F 类型那一行的 `perms`。

## 4. 数据库设计

- [ ] 🔴 **逻辑删除 + 唯一索引冲突**
  删掉的用户还占着 `username` 唯一键，重建同名用户直接报错。
  做法：唯一索引带上 `del_flag`（`uk_username_del(username, del_flag)`），或删除时把 username 改名加后缀。

- [ ] 🔴 **时区全链路统一**
  三个地方必须一致：JVM（`-Duser.timezone=Asia/Shanghai`）、MySQL（`serverTimezone=Asia/Shanghai`）、容器（`TZ=Asia/Shanghai`）。
  不一致的典型症状：数据库里时间比页面少 8 小时，或者定时任务半夜跑。

- [ ] 🟡 **字段规范**
  金额一律 `decimal(18,2)`，禁止 `float/double`；时间 `datetime(3)`；字符集 `utf8mb4` + `utf8mb4_0900_ai_ci`；布尔用 `tinyint(1)`。

- [ ] 🟡 **审计字段统一**：`create_by / create_time / update_by / update_time / del_flag / remark`，用 MP 的 `MetaObjectHandler` 自动填充，别在每个 Service 里手写。

- [ ] 🟡 **索引原则**
  区分度高的列在前；联合索引遵守最左前缀；不要在索引列上用函数（`where date(create_time) = ...` 会失效）；上线前 `explain` 看一遍。

- [ ] 🟡 **深分页**
  `limit 100000, 10` 会扫描 10 万行。后台列表用游标分页（`where id < lastId`）或延迟关联。

- [ ] 🟡 **不要用外键**，业务库靠应用层保证，否则迁移和批量操作会被卡死。

- [ ] 🟡 **大字段拆表**：`text`/`blob` 单独放扩展表，否则主表查询会被拖慢。

- [ ] 🟢 **Flyway 脚本只增不改**，生产禁止 `flyway.clean`。已执行的脚本改一个字都会导致校验失败。

- [ ] 🟢 **连接池用 HikariCP**（Boot 默认），不要引 Druid——Boot 4 下兼容性和收益都不划算。

## 5. 事务与并发

- [ ] 🔴 **`@Transactional` 失效的五种情况**
  1. 类内自调用（`this.saveXxx()` 不走代理）
  2. 方法不是 `public`
  3. 异常被 `catch` 吞掉没重新抛
  4. 抛的是受检异常（默认只回滚 `RuntimeException` 和 `Error`）
  5. 类没被 Spring 管理（手动 `new` 出来的）
  自查口诀：**事务方法必须是被注入的 bean 调用的 public 方法，且异常要抛出去。**

- [ ] 🔴 **事务里不做耗时操作**
  远程调用、发 MQ、生成 Excel、上传 OSS 都不要放在事务内。连接被占着，高并发下连接池瞬间打满。

- [ ] 🟡 **控制事务粒度**：不要在 Controller 层开事务，也不要把整个 request 包在一个事务里。

- [ ] 🟡 **日志/审计用 `REQUIRES_NEW`**：业务回滚了，操作日志还要留下来。

- [ ] 🔴 **写操作要幂等**
  前端重复点击、网络重试、MQ 重投都会导致重复下单/重复扣款。
  做法：唯一索引兜底 + Redis 防重 token（提交前取，提交时删）。

- [ ] 🟡 **并发更新用乐观锁**
  MP 的 `OptimisticLockerInnerInterceptor` + `version` 字段。别用"先查再改"，中间有窗口期。

- [ ] 🟡 **库存类扣减用 SQL 原子操作**
  `update ... set stock = stock - #{n} where id = ? and stock >= #{n}`，看影响行数判断成败，不要先 select 再 update。

- [ ] 🟡 **分布式锁用 Redisson，不要手写 `setnx`**
  手写版三大坑：没续期（业务超时锁自动释放）、误删别人的锁、不可重入。

## 6. Redis 与缓存

- [ ] 🔴 **key 规范统一**：`业务:模块:标识`，如 `admin:user:perms:1`。**所有 key 必须有过期时间**（除极少数永久配置），否则 Redis 会慢慢涨满。

- [ ] 🔴 **禁止 `KEYS *`**，用 `SCAN` 游标遍历。`KEYS` 在大库上会阻塞整个实例。

- [ ] 🔴 **缓存三兄弟**
  穿透（查不存在的数据）→ 空值缓存 + 短 TTL，或布隆过滤器
  击穿（热点 key 过期瞬间）→ 互斥重建 / 逻辑过期
  雪崩（大批 key 同时过期）→ TTL 加随机偏移

- [ ] 🔴 **更新策略：先更新 DB，再删缓存**（不是更新缓存）。接受短暂不一致，配延迟双删兜底。反过来（先删缓存再更库）在并发下必然脏数据。

- [ ] 🟡 **序列化统一用 JSON**，不要用 JDK 序列化——不可读、跨语言不通、类改字段就反序列化失败。

- [ ] 🟡 **大 key 治理**：单个 value 超过 10KB、或集合元素过万，要拆分。大 key 删除会阻塞。

- [ ] 🟡 **热 key**：秒杀/首页配置这类，本地缓存 + Redis 二级，别让所有请求打同一个 key。

- [ ] 🟡 **Redis 不是数据库**：持久化开了也不代表数据安全。核心数据必须落 MySQL，Redis 只做加速。

- [ ] 🟡 **连接池**：Lettuce 默认共享连接，注意 `shareNativeConnection`；不要在 Redis 里跑超过 100ms 的 Lua 脚本。

## 7. 接口契约（前后端最容易扯皮的地方）

- [ ] 🔴 **统一返回体**：`{ code, msg, data, traceId }`。错误码用枚举，不要各写各的。

- [ ] 🔴 **时间格式统一**：`yyyy-MM-dd HH:mm:ss`，全局配一次，别让每个 DTO 打 `@JsonFormat`。

- [ ] 🟡 **分页参数上限**：`pageSize` 必须卡上限（比如 100），否则 `pageSize=999999` 一次拖垮数据库。

- [ ] 🟡 **参数校验用 `@Valid` + 全局异常处理**，`MethodArgumentNotValidException` 要转成友好提示，不能把堆栈返回给前端。

- [ ] 🟡 **错误信息不暴露内部细节**：生产环境返回"系统繁忙"，堆栈只进日志。SQL 报错原文返回给前端等于告诉攻击者表结构。

- [ ] 🟡 **文件上传**：大小限制、扩展名白名单（不能只信 `Content-Type`）、重命名存储、**不返回服务器物理路径**、上传目录禁止脚本执行权限。

- [ ] 🟡 **导出 Excel 用流式**（EasyExcel / SXSSF），一次性 `select *` 全表必 OOM。大数据量走异步导出 + 下载中心。

- [ ] 🟢 **接口加 traceId**：响应头 + 日志 MDC 都带上，排查问题时能串起一整条链路。

## 8. 前端工程

- [ ] 🔴 **动态路由刷新后白屏/404**
  路由是登录后 `addRoute` 加的，刷新时页面还没登录态、路由表是空的。
  做法：路由守卫里先 `await` 拉用户信息和菜单 → `addRoute` → `next({ ...to, replace: true })`。

- [ ] 🔴 **axios 401 并发刷新风暴**
  10 个请求同时 401，触发 10 次 refresh，token 互相覆盖，最后全部失效。
  做法：模块级 `isRefreshing` 标志 + 等待队列，刷新完成后统一重放。

- [ ] 🔴 **守卫死循环**
  跳登录页时没把 `/login` 加进白名单，或 403 也跳登录页，导致无限重定向。浏览器直接卡死。

- [ ] 🟡 **错误提示防抖**：一个接口失败弹 3 个 toast 很常见。统一在拦截器里做「同一条消息 2 秒内只弹一次」。

- [ ] 🟡 **按钮防重复提交**：提交时 `loading` 置 true，请求结束再放开。光靠后端幂等不够，体验也差。

- [ ] 🟡 **分页参数对齐**：后端从 1 开始还是从 0 开始，`pageNum` 还是 `page`，`size` 还是 `pageSize`——写进接口文档，别凭记忆。

- [ ] 🟡 **表格大数据量**：超过 1000 行换 `el-table-v2`（虚拟滚动），普通 `el-table` 会明显卡顿。

- [ ] 🟡 **环境变量**：`.env.development` / `.env.production` 管 `baseURL`，别把 `localhost:8000` 写死在代码里。

- [ ] 🟢 **打包体积**：Element Plus 按需引入、路由懒加载、`manualChunks` 拆 vendor，首屏能差 3 倍。

- [ ] 🟢 **Nginx history 模式**：`try_files $uri $uri/ /index.html;`，否则刷新子路由 404。

## 9. 安全

- [ ] 🔴 **SQL 注入**：MyBatis 一律 `#{}`，禁止 `${}` 拼接用户输入。`order by ${column}` 这种动态排序必须做白名单校验。

- [ ] 🔴 **XSS**：富文本内容后端过滤（如 OWASP Sanitizer），前端不要用 `v-html` 渲染用户输入。

- [ ] 🟡 **CSRF**：JWT 放 Header 模式天然免疫；如果 token 放 Cookie，必须开 CSRF 防护 + `SameSite`。

- [ ] 🟡 **日志脱敏**：密码、手机号、身份证、银行卡在日志里打印前脱敏。别 `log.info("user: {}", JSON.toJSONString(user))`。

- [ ] 🟡 **接口限流**：登录、验证码、短信、导出这几类必须限流（Redis 计数或 Sentinel）。

- [ ] 🟡 **生产环境关闭**：Swagger / Knife4j / Actuator 全端点 / H2 控制台 / Druid 监控页。

- [ ] 🟡 **默认口令**：`admin/admin123` 必须首次登录强制改密，或者初始化时随机生成打印到日志。

- [ ] 🟢 **依赖漏洞扫描**：`mvn dependency-check` 或 Dependabot，每周跑一次。

## 10. 部署与运维

- [ ] 🔴 **容器时区**：基础镜像默认 UTC，`TZ=Asia/Shanghai` + JVM `-Duser.timezone` 都要设，否则日志时间和业务时间对不上。

- [ ] 🟡 **JVM 堆要和容器 limit 匹配**：`-XX:MaxRAMPercentage=75`，别让 JVM 无脑吃掉宿主机内存被 OOMKill。

- [ ] 🟡 **优雅停机**：`server.shutdown=graceful`，配合 K8s 的 `preStop`，否则发版时正在处理的请求全部 502。

- [ ] 🟡 **日志滚动**：`logback` 配 `SizeAndTimeBasedRollingPolicy`，不配的话日志能把磁盘写满。生产级别用 INFO，别开 DEBUG。

- [ ] 🟡 **数据库备份 + 恢复演练**：备份了不代表能恢复，每季度做一次恢复验证。

- [ ] 🟡 **配置外置 + 敏感信息加密**：数据库密码不要明文躺在 Git 里，用环境变量或配置中心。

- [ ] 🟢 **HTTPS + 反向代理头**：Nginx 要传 `X-Forwarded-For/Proto`，后端配 `server.forward-headers-strategy=native`，否则拿到的客户端 IP 全是 127.0.0.1。

## 11. 代码工程

- [ ] 🟡 **Entity 不要直接返回给前端**
  会泄露不该暴露的字段（密码、盐、内部标记），还容易触发懒加载/序列化异常。
  统一 DTO（入参）/ VO（出参）/ Entity（持久化）三层。

- [ ] 🟡 **全局异常兜底**：`@RestControllerAdvice` 捕获 `Exception`，但**不要吞掉**——要打日志 + traceId，返回统一错误结构。

- [ ] 🟡 **N+1 查询**：循环里查数据库，10 条数据 11 次 SQL。用 `in` 批量查或 join。

- [ ] 🟡 **循环依赖**：A 依赖 B、B 依赖 A，靠 `@Lazy` 掩盖只是延后爆炸。该拆 Service。

- [ ] 🟡 **不要在 Service 里塞 Wrapper**：超过 3 个 `LambdaQueryWrapper` 串联就该考虑写 XML 或独立 Mapper 方法。

- [ ] 🟢 **单元测试覆盖权限逻辑**：`@PreAuthorize` 是否生效、数据权限 SQL 是否正确，这两块最容易静默出错。

## 12. 上线前 20 项自检

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 所有接口都有鉴权注解 | 全局搜索 `@RequestMapping` 与 `@PreAuthorize` 数量对得上 |

| 7 | 分页上限 | `pageSize=100000` 被拒绝或截断 |
