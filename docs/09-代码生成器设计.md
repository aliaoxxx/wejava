# 09 · 代码生成器设计

> 目标：读数据库表 → 一键生成后端 8 个文件 + 前端 `api.ts` / `schema.ts` + 菜单 SQL，
> 把"新增一张表"的成本从**半天手写**降到**1 分钟**。
> 状态：**P1 已实现**（V16 迁移 + 导入/配置/预览/下载 + 12 个模板 + 页面）。

---

## 一、为什么做

前端已经是配置驱动的（`schema.ts` → 页面），但后端仍是纯手工。一个完整 CRUD 模块要写：

| 层 | 文件 | 容易漏的点 |
|---|---|---|
| 实体 | `SysXxx.java` | `@TableId` 策略、`@TableName`、继承 `BaseEntity` |
| Mapper | `SysXxxMapper.java` | 继承 `BaseMapper` |
| Service / Impl | 2 个 | 分页查询条件、`LambdaQueryWrapper` 拼装 |
| Controller | 1 个 | `@PreAuthorize` 权限字符、`@OperLog`、`@Valid` |
| VO / Form / Query | 3–4 个 | `@Schema` 描述、分页字段、校验注解 |
| Converter | 1 个 | MapStruct 接口 |
| 前端 | `api.ts` + `schema.ts` | 接口函数、字段类型、字典 |

**手写耗时约 4–6 小时，且每次都在重复同样的判断**。生成器要消灭的就是这部分。

## 三、元数据存储（V16 迁移，新增 2 张表）

参考 RuoYi 的做法：导入一次，配置持久化，团队可以共用。

```sql
CREATE TABLE `gen_table`
(
    `table_id`      bigint NOT NULL AUTO_INCREMENT COMMENT '配置ID',
    `table_name`    varchar(200) NOT NULL COMMENT '表名',
    `table_comment` varchar(500) DEFAULT NULL COMMENT '表描述',
    `class_name`    varchar(100) NOT NULL COMMENT '实体类名',
    `module_name`   varchar(50)  NOT NULL COMMENT '模块名，如 system',
    `business_name` varchar(50)  NOT NULL COMMENT '业务名，如 notice',
    `function_name` varchar(100) NOT NULL COMMENT '功能名，用于菜单',
    `package_name`  varchar(200) NOT NULL DEFAULT 'com.wejava.system' COMMENT '包名',
    `author`        varchar(50)  DEFAULT NULL,
    `parent_menu_id` bigint      DEFAULT NULL COMMENT '挂到哪个菜单下',
    `create_time`   datetime(3)  DEFAULT NULL,
    `update_time`   datetime(3)  DEFAULT NULL,
    PRIMARY KEY (`table_id`),
    UNIQUE KEY `uk_table_name` (`table_name`)
) COMMENT '代码生成-表配置';

CREATE TABLE `gen_table_column`
(
    `column_id`     bigint NOT NULL AUTO_INCREMENT,
    `table_id`      bigint NOT NULL COMMENT '所属表配置',
    `column_name`   varchar(200) NOT NULL COMMENT '列名',
    `column_type`   varchar(100) NOT NULL COMMENT '列类型',
    `column_comment` varchar(500) DEFAULT NULL,
    `java_type`     varchar(50)  NOT NULL COMMENT 'Java 类型',
    `java_field`    varchar(100) NOT NULL COMMENT 'Java 属性名',
    `is_pk`         tinyint      NOT NULL DEFAULT 0,
    `is_increment`  tinyint      NOT NULL DEFAULT 0,
    `is_required`   tinyint      NOT NULL DEFAULT 0,
    `is_insert`     tinyint      NOT NULL DEFAULT 1 COMMENT '新增表单显示',
    `is_edit`       tinyint      NOT NULL DEFAULT 1 COMMENT '编辑表单显示',
    `is_list`       tinyint      NOT NULL DEFAULT 1 COMMENT '列表显示',
    `is_query`      tinyint      NOT NULL DEFAULT 0 COMMENT '作为查询条件',
    `query_type`    varchar(20)  DEFAULT 'EQ' COMMENT 'EQ / LIKE / BETWEEN',
    `html_type`     varchar(20)  DEFAULT 'input' COMMENT '表单控件',
    `dict_type`     varchar(100) DEFAULT NULL COMMENT '字典编码',
    `sort`          int          NOT NULL DEFAULT 0,
    PRIMARY KEY (`column_id`),
    KEY `idx_table_id` (`table_id`)
) COMMENT '代码生成-字段配置';
```

## 四、类型映射规则（自动推断，可人工覆盖）

| MySQL 类型 | Java | TS | 表单控件 |
|---|---|---|---|
| `bigint` | `Long` | `number` | `number` |
| `int` / `tinyint` | `Integer` | `number` | `number` / `switch`（值为 0/1 时） |
| `varchar(n)` | `String` | `string` | n ≤ 255 → `input`，否则 `textarea` |
| `text` / `longtext` | `String` | `string` | `textarea` |
| `datetime` / `timestamp` | `LocalDateTime` | `string` | `datetime` |
| `date` | `LocalDate` | `string` | `date` |
| `decimal` / `double` | `BigDecimal` | `number` | `number` |

**列名推断规则**

| 列名 | 推断 |
|---|---|
| `xxx_id` 且是主键 | 主键，列表可见、表单不显示 |
| `status` | 查询条件 + `select`，字典 `sys_normal_disable` |
| `sort` / `order_num` | `number` |
| `remark` | `textarea`，列表不显示 |
| `create_time` / `update_time` / `create_by` / `update_by` | 列表显示，表单不显示（来自 `BaseEntity`） |

## 五、命名规则

| 项 | 规则 | 示例 |
|---|---|---|
| 表名 | `{module}_{business}` | `system_notice` |
| 实体类 | 全表名驼峰 | `SystemNotice` |
| 变量名 | 业务名驼峰（小写开头） | `notice` |
| 权限前缀 | `{module}:{business}` | `system:notice` |
| 后端路由 | `/{module}/{business}` | `/system/notice` |
| 前端目录 | `views/{module}/{business}/` | `views/system/notice/` |

> 前缀不强制 `sys_`：`system_notice` 和 `notice` 都能正确推导，前者更清晰。

## 六、接口设计

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/system/gen/table/list` | `system:gen:list` | 已导入的表 |
| GET | `/system/gen/table/db/list` | `system:gen:list` | **未导入**的数据库表（读 `information_schema`） |
| POST | `/system/gen/table/import` | `system:gen:import` | 导入指定表，自动推断字段 |
| GET | `/system/gen/table/{id}` | `system:gen:query` | 表配置详情（含字段） |
| PUT | `/system/gen/table/{id}` | `system:gen:edit` | 保存表与字段配置 |
| DELETE | `/system/gen/table/{id}` | `system:gen:remove` | 删除配置（不删业务表） |
| GET | `/system/gen/preview/{id}` | `system:gen:preview` | 返回 `Map<文件名, 代码内容>` |
| GET | `/system/gen/download/{id}` | `system:gen:code` | 下载 zip |
| POST | `/system/gen/batch-download` | `system:gen:code` | 批量下载 |

**下载 zip 的目录结构**

```
wejava-{business}.zip
├── backend/…   （9 个 Java 文件，按包路径分层）
├── frontend/
│   ├── api/{module}/{business}.ts
│   └── views/{module}/{business}/schema.ts
└── sql/menu_{table}.sql
```

## 七、模板引擎

用 **FreeMarker**（Spring Boot 已内置 `spring-boot-starter-freemarker` 的自动配置能力，也可只引 `freemarker` 依赖手动配置）。

模板放 `src/main/resources/template/gen/`：

```
entity.java.ftl
mapper.java.ftl
service.java.ftl
serviceImpl.java.ftl
controller.java.ftl
vo.java.ftl
form.java.ftl
query.java.ftl
converter.java.ftl
api.ts.ftl
schema.ts.ftl
menu.sql.ftl
```

**为什么用模板文件而不是字符串拼接**：模板可以热改，用户能按自己项目风格替换，不必动 Java 代码。

## 八、生成器页面

新增菜单「系统工具 → 代码生成」，页面不自用 schema（它本身是特殊的），手写：

```
1. 表列表（已导入）      → 预览 / 编辑 / 下载 / 删除
2. 「导入表」按钮        → 弹窗列出数据库中未导入的表（带注释）
3. 「编辑」              → 表基本信息 + 字段配置表格（可勾选列角色、改控件类型、绑字典）
4. 「预览」              → 左侧文件树 + 右侧代码（带语法高亮）
```

## 九、安全约束

| 风险 | 处理 |
|---|---|
| 生成器被普通用户使用 | 全部接口 `@PreAuthorize` + 只授予超管 |
| 读到了不该读的表 | 白名单：只读 `information_schema`，**排除 `gen_*`、`sys_*`（可选）** |
| 直接在服务器写文件 | **不做**，只生成 zip 下载，避免路径穿越与误覆盖 |
| 生成含 SQL 注入的代码 | 只做文本模板，不拼接用户输入到 SQL |
| 下载包过大 | 单次最多 20 张表，超出拒绝 |

## 十一、验收标准

- [ ] 导入一张新表（如 `demo_product`），字段类型、必填、查询条件自动推断正确
- [ ] 生成的后端代码放进项目能**直接编译通过**，且 `spotless:check` 通过
- [ ] 生成的 `schema.ts` 能通过 `vue-tsc`，页面增删改查可用
- [ ] 生成的 `menu.sql` 执行后菜单与按钮权限齐全
- [ ] 预览接口返回的代码与下载 zip 内容一致
- [ ] 非超管访问生成器接口返回 403

## 十三、实现记录（P1）

| 项 | 结果 |
|---|---|
| 迁移 | `V16__code_generator.sql`：2 张配置表 + 代码生成菜单与 5 个按钮权限 |
| 模板 | 12 个 `.ftl`，放 `resources/template/gen/` |
| 产物 | 实际生成 **13 个文件**（12 个代码/配置 + 1 个 `README.txt`） |
| 页面 | 系统管理 → 代码生成，列表 / 导入 / 编辑 / 预览 / 下载 / 删除 |

**一个值得记录的细节**：模板要按 palantir 的 120 列规则决定是否折行，
否则生成的代码能编译但过不了 `spotless:check`。做法是在模型里按
`83 + 3×字段名长度 + 类名长度` 估算行宽，超过 120 才输出折行版本。

**实测结果**（在测试库建 `demo_product` 演示）：

```
字段推断     大字段 → textarea，status → switch + 字典，审计字段 → 表单隐藏
生成代码     9 个 Java 文件一次编译通过，spotless:check 直接通过
前端产物     schema.ts 通过 vue-tsc，api.ts 通过 lint
菜单 SQL     菜单 + 5 个按钮权限，role_id=1 自动授权
下载         zip 8.2 KB，目录结构与设计一致
```

## 十二、不做的事（明确边界）

- ❌ 不做"运行时低代码"（元数据驱动动态接口）——那是产品方向，不是生成器
- ❌ 不自动写入服务器文件系统
- ❌ 不生成 Flyway 迁移（业务表由开发自己建，生成器只生成代码）
