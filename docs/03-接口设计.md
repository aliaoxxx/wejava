# 03 · 接口设计

> 基础路径：开发环境 `http://localhost:8000/dev/api`，生产环境 `/prod/api`
> 除登录、验证码、刷新外，所有接口要求 `Authorization: Bearer <access_token>`
>
> 在线文档：开发/演示环境可用 Swagger UI（`/dev/api/swagger-ui/index.html`、`/api/swagger-ui/index.html`），
> 点 **Authorize** 填入 accessToken 即可调试；生产环境通过 `springdoc.api-docs.enabled=false` 关闭。

---

## 一、通用约定

| 项 | 约定 |
|---|---|
| 编码 | UTF-8 |
| 请求体 | `application/json`（文件上传除外） |
| 时间格式 | `yyyy-MM-dd HH:mm:ss`（传输），`datetime(3)`（存储） |
| Long 型 ID | **序列化为字符串**，前端按 string 处理 |
| 空值 | `null` 字段保留（不裁剪），便于前端判断 |
| 分页参数 | `pageNum`（从 1 开始）、`pageSize`（默认 10，上限 100） |
| 排序参数 | `orderBy`（字段名，白名单校验）、`orderDirection`（`asc`/`desc`） |
| 路径风格 | 全小写 + 短横线：`/system/user/reset-pwd` |
| 幂等 | 写接口支持 `Idempotency-Key` 头（可选） |

## 二、统一返回体

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {},
  "traceId": "b7c1f3e2a9d84c5e"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | 见错误码表，`200` 表示成功 |
| `msg` | string | 用户可读的提示语 |
| `data` | any | 业务数据，无数据时为 `null` |
| `traceId` | string | 链路追踪 ID，报错时提供给客服/运维 |

### 分页返回

```json
{
  "code": 200,
  "msg": "ok",
  "data": {
    "total": 128,
    "list": [ { "userId": "1", "username": "admin" } ]
  },
  "traceId": "..."
}
```

## 三、错误码表

### 3.1 HTTP 层

| code | HTTP | 含义 | 前端处理 |
|---|---|---|---|
| `200` | 200 | 成功 | — |
| `400` | 400 | 参数校验失败 | 提示 `msg` |
| `401` | 401 | 未认证 | 见下方细分 |
| `403` | 403 | 无权限 | 提示，**不跳转** |
| `404` | 404 | 资源不存在 | 提示 |
| `405` | 405 | 方法不允许 | 提示 |
| `429` | 429 | 请求过于频繁 | 提示稍后重试 |
| `500` | 500 | 系统异常 | 提示"系统繁忙" + traceId |

### 3.2 认证细分

| code | 含义 | 前端行为 |
|---|---|---|
| `1001` | 用户名或密码错误 | 提示，留在登录页 |
| `1002` | 账号已停用 | 提示 |
| `1003` | 账号已锁定 | 提示剩余时间 |
| `1004` | 验证码错误或已过期 | 刷新验证码 |
| `1005` | access token 已过期 | **静默刷新**并重放请求 |
| `1006` | token 无效 / 会话已失效 | 清状态，跳登录页 |
| `1007` | 原密码错误 | 提示 |
| `1008` | 两次输入的密码不一致 | 提示 |
| `1009` | 新密码不能与原密码相同 | 提示 |

### 3.3 业务层

| code | 含义 |
|---|---|
| `2001` | 数据不存在 |
| `2002` | 数据已存在（名称/编码重复） |
| `2003` | 存在子节点，无法删除 |
| `2004` | 存在关联数据，无法删除 |
| `2005` | 不允许操作超级管理员 |
| `2006` | 不允许操作当前登录用户 |
| `2007` | 部门下存在用户，无法删除 |
| `2008` | 角色已分配给用户，无法删除 |

### 3.4 文件与导出

| code | 含义 |
|---|---|
| `3001` | 文件上传失败 |
| `3002` | 文件类型不允许 |
| `3003` | 文件大小超出限制 |
| `3004` | 导出数据量过大，请缩小范围 |
| `3005` | 文件不存在或已过期 |

## 四、认证接口

### 4.1 获取验证码

```
GET /auth/captcha
```

无需认证。响应：

```json
{
  "code": 200,
  "msg": "ok",
  "data": {
    "captchaKey": "8f14e45fceea167a5a36dedd4bea2543",
    "captchaImage": "data:image/png;base64,iVBORw0KGgo..."
  }
}
```

| 字段 | 说明 |
|---|---|
| `captchaKey` | 本次验证码标识，登录时回传 |
| `captchaImage` | base64 图片，可直接放 `<img src>` |

### 4.2 登录

```
POST /auth/login
```

```json
{
  "username": "admin",
  "password": "admin123",
  "captchaKey": "8f14e45fceea167a5a36dedd4bea2543",
  "captchaCode": "12"
}
```

```json
{
  "code": 200,
  "msg": "登录成功",
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiIs...",
    "refreshToken": "eyJhbGciOiJIUzI1NiIs...",
    "expiresIn": 1800,
    "tokenType": "Bearer"
  }
}
```

### 4.3 刷新 Token

```
POST /auth/refresh
```

```json
{ "refreshToken": "eyJhbGciOiJIUzI1NiIs..." }
```

响应同登录。**旧 refresh 立即失效**（rotation），重复使用返回 `1006`。

### 4.4 登出

```
POST /auth/logout
```

无请求体，从 `Authorization` 头取 token。响应 `R<Void>`。

### 4.5 获取当前用户信息

```
GET /auth/me
```

```json
{
  "code": 200,
  "data": {
    "user": {
      "userId": "1",
      "username": "admin",
      "nickname": "超级管理员",
      "avatar": null,
      "deptId": "100",
      "deptName": "WeJava 科技"
    },
    "roles": ["admin"],
    "perms": ["*:*:*"],
    "superAdmin": true
  }
}
```

### 4.6 获取动态路由（菜单树）

```
GET /auth/routers
```

返回前端可直接挂载的路由树，只含 `menu_type` 为 `M` 和 `C` 的节点：

```json
{
  "code": 200,
  "data": [
    {
      "name": "System",
      "path": "/system",
      "component": "Layout",
      "redirect": "/system/user",
      "meta": { "title": "系统管理", "icon": "setting", "hidden": false },
      "children": [
        {
          "name": "SystemUser",
          "path": "user",
          "component": "system/user/index",
          "meta": { "title": "用户管理", "icon": "user", "cache": false }
        }
      ]
    }
  ]
}
```

### 4.7 修改密码

```
PUT /auth/password
```

```json
{ "oldPassword": "admin123", "newPassword": "Abc@123456" }
```

成功后**强制下线**（清空该用户全部会话），前端跳登录页。

## 五、用户管理

路径前缀 `/system/user`

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/list` | `system:user:list` | 分页查询 |
| GET | `/{userId}` | `system:user:query` | 详情（含角色/岗位 ID） |
| POST | `` | `system:user:add` | 新增 |
| PUT | `` | `system:user:edit` | 修改 |
| DELETE | `/{userIds}` | `system:user:remove` | 删除（逗号分隔支持批量） |
| PUT | `/reset-pwd` | `system:user:resetPwd` | 重置密码 |
| PUT | `/change-status` | `system:user:edit` | 启用/停用 |
| GET | `/export` | `system:user:export` | 导出 Excel |
| GET | `/import-template` | `system:user:import` | 下载导入模板 |

### 查询参数

| 参数 | 类型 | 说明 |
|---|---|---|
| `pageNum` / `pageSize` | int | 分页 |
| `username` | string | 模糊 |
| `nickname` | string | 模糊 |
| `phone` | string | 模糊 |
| `status` | int | 精确 |
| `deptId` | long | **含子部门** |
| `beginTime` / `endTime` | string | 创建时间区间 |

### 列表返回项

```json
{
  "userId": "1",
  "deptId": "100",
  "deptName": "WeJava 科技",
  "username": "admin",
  "nickname": "超级管理员",

  "sex": "0",
  "status": 0,
  "loginIp": "127.0.0.1",
  "loginDate": "2026-10-27 13:20:00",
  "createTime": "2026-10-01 09:00:00"
}
```

> 列表**不返回** `password`、`delFlag`、`pwdUpdateTime`。

### 新增/修改请求

```json
{
  "deptId": "101",
  "username": "zhangsan",
  "nickname": "张三",
  "password": "Abc@123456",
  "email": "zs@wejava.dev",

  "postIds": ["1"],

```

> `password` 仅新增时必填；修改时不传则不改密码。


| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/common/upload` | 登录即可 | 单文件上传，返回 `{url, name, size}` |

## 十四、SSE 实时通道

站内消息通过 SSE 推送。EventSource 不能设置请求头，所以用**一次性票据**换连接。

| 步骤 | 接口 | 说明 |
|---|---|---|
| 1 | `POST /auth/sse-ticket` | 需 Bearer 鉴权，返回 `{ ticket, expiresIn }` |
| 2 | `GET /stream/notifications?ticket=xxx` | 建立事件流，票据 30 秒有效、用后即删 |

### 事件格式

```
event:connected
data:{"userId":"1"}

event:message
data:{"messageId":"5","title":"...","msgType":1,"level":0}

:ping

```

| event | 触发时机 | data |
|---|---|---|
| `connected` | 连接建立 | `{ userId }` |
| `message` | 新公告 / 系统消息投递 | 消息摘要 |
| `unread` | 未读数变化 | `{ count }` |
| 注释行 `:ping` | 每 15 秒 | 防止中间代理掐断空闲连接 |

### 传输层要求

```
Content-Type: text/event-stream; charset=utf-8
Cache-Control: no-cache, no-transform
X-Accel-Buffering: no
```

Nginx 反代时必须关闭缓冲，否则事件会被攒着不发：

```nginx
location /prod/api/stream/ {
    proxy_pass http://127.0.0.1:8080/prod/api/stream/;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 3600s;
}
```

### 跨实例

`SseEmitter` 存在单实例内存里，多副本部署时消息可能推到别的节点。
投递链路统一走 Redis Pub/Sub（频道 `admin:sse:user:{userId}`），
各实例订阅后只推给本地在线连接；广播消息带 `from` 实例标识，避免自己消费自己导致重复推送。

## 十五、站内消息与 AI

### 15.1 站内消息 `/system/message`

个人数据，登录即可访问，不设权限点。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/unread-count` | 未读数 |
| GET | `/list` | 收件箱分页（msgType / readFlag / keyword） |
| GET | `/{messageId}` | 详情，非本人消息返回 403 |
| PUT | `/{messageId}/read` | 标记已读 |
| PUT | `/read-all` | 全部已读 |
| POST | `/send` | 后台发送，权限 `system:message:send` |

发送请求体：

```json
{
  "title": "系统维护通知",
  "content": "今晚 23:00 起维护",
  "msgType": 2,
  "level": 1,
  "targetType": 3,
  "targetIds": [101],
  "link": "/system/notice"
}
```

`targetType`：1 全员 / 2 按角色 / 3 按部门 / 4 指定用户。
部门匹配走 `FIND_IN_SET` 匹配 `ancestors`，选父部门会自动包含子部门成员。

### 15.2 公告定向投递

`sys_notice` 增加 `target_type` / `target_ids`，发布时复用同一套接收人解析。
历史数据默认 `target_type = 1`（全员），行为不变。

### 15.3 AI 对话 `/ai`

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/chat` | 流式对话，返回 `text/event-stream` |
| GET | `/session/{sessionId}/messages` | 会话历史 |

事件：`delta`（增量文本）/ `done`（用量与耗时）/ `error`（失败原因）。

```json
{"sessionId": "1", "content": "你好"}
```

### 15.4 AI 配置 `/system/ai-config`

| 方法 | 路径 | 权限 |
|---|---|---|
| GET | `/system/ai-config` | `system:ai:config` |
| PUT | `/system/ai-config` | `system:ai:config` |

密钥以 AES-GCM 加密存储，**接口只返回掩码**（如 `xxxx****xxxx`）；
提交空值或掩码表示保留原密钥。加密密钥来自环境变量 `AI_CONFIG_SECRET`。

### 15.5 生产环境启动校验

生产 profile（`prod`）启动时校验 `JWT_SECRET` 与 `AI_CONFIG_SECRET`，
仍为开发默认值时进程直接退出，避免带着可被破解的密钥上线。
